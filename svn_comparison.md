# Git vs SVN — ответы на вопросы

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто **указатель** на один коммит (файл размером
41 байт). Создание ветки — это запись 41 байта, поэтому мгновенно.

В SVN ветка — это **полная копия директории** внутри репозитория.
Файлы физически дублируются на сервере. Чем больше проект, тем
дольше создание ветки и тем больше она занимает места. Поэтому
в SVN ветки создают редко, а в Git — постоянно.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

**Нет.** SVN — централизованная система, у неё один сервер, где
хранится вся история. Коммит — это отправка изменений на сервер,
поэтому без сети он невозможен. Локально можно только редактировать
файлы, но зафиксировать изменения — нет.

В Git коммит делается в **локальный** репозиторий (у каждого есть
полная копия), поэтому коммитить можно офлайн. Пуш откладывается
до появления интернета.

## 3. В каких сценариях SVN может быть предпочтительнее Git?

- **Огромные бинарные файлы** (видео, 3D-модели, дизайн). SVN умеет
  делать частичный checkout (только нужную папку), а Git клонирует
  весь репозиторий — при размере в сотни ГБ это проблема.
- **Жёсткая централизация и контроль доступа.** В банках и госсекторе
  нужен единый сервер с аудитом — SVN здесь проще администрировать.
- **Старые проекты (legacy).** Если проект 15 лет на SVN, миграция
  на Git может стоить дороже, чем оставить как есть.
